# 《AI异常调查局》产品设计

> **状态：V1 Legacy。** 2026-08-13 起默认玩家体验进一步切换到 `Simulator V3 / Construction Sandbox`。V1 与 V2 都保留为实验资产，但不再作为新核心玩法的 source of truth。当前方向见 [`SIMULATOR_V3.md`](SIMULATOR_V3.md)。

## 一句话定位
一款把机器学习系统拆成可操作调查谜题的浏览器游戏。新人从“橘猫被识别成面包”建立训练 / 未知数据直觉，随后通过连续手工案件逐步加入分类别指标、阈值取舍、环境变化与控制变量，再把这些方法带进程序化 Duty。CASE 001 的 **20～30 分钟**仍只是首个长篇 onboarding 的设计目标；CASE 002+ 刻意改成更短、更可组合的系统谜题。

## 玩家画像
- 大一新生；可能完全没学过机器学习、线性代数、概率论和 Python。
- 对 AI 有兴趣，但对公式、代码和英文术语有明显心理门槛。
- 第一次社团活动中需要迅速获得“我能做到”的反馈。

## 学习目标
通关后，玩家能够用自己的话解释：
1. 模型只能利用提供给它的数据与特征。
2. 训练集上表现好，不代表未知数据上也表现好。
3. 模型越复杂不一定越好；过度迎合训练数据会伤害未知数据表现。
4. 测试集用于检查模型面对未知数据时的表现。
5. 错误样本比单个准确率数字更能帮助定位问题。

## 第一关体验流程
### Cold Open：事故发生（约 2～3 分钟）
- 先进入校园夜间监控录像，而不是直接掉进 ML 工作台。
- 玩家亲眼看到橘猫被系统输出为 `BREAD / 87%`，并完成第一个唯一显眼操作：“这明明是一只猫”。
- 系统显示 `CAT ≠ BREAD / CONFLICT DETECTED`，小析才介入说明案件目标：找出机器人学错了什么，并让它面对没见过的新样本也能判断稳定。
- 这段同时教会玩家游戏的点击视觉语言，不要求任何 ML 背景。

### 阶段 1：第一次成功（约 5～7 分钟）
- 身份：现场调查员 → 传感器调查员 → 模型工程师。
- 工作台采用 progressive disclosure：还没用到的模型、特征工具直接隐藏，而不是全部同时变灰摆在屏幕上。
- 玩家先肉眼判断旧样本是否形成两团，随后必须直接在散点图上抓出一个“站进对面阵营”的异常旧样本；散点图是可操作棋盘而不是背景图。
- 分别读取“颜色暖度 / 轮廓圆度”两个当前观察通道，理解机器人并没有像人一样直接看懂图片。
- 玩家亲手装载唯一开放的直线分类器并训练；训练后先读取一个没有真值的 `PROBE ?`，判断模型会把它放到哪一侧，明确“模型会说什么”与“真实答案是什么”不是同一问题。
- 之后才留下“它是否真的修好”的现实预测，再开放未知样本验证。
- 此时仍不提前解释训练集、测试集、泛化、过拟合等术语。

### 阶段 2：意外失败（约 6～8 分钟）
- 身份切换为系统审计员。
- 首次揭示一批此前不可见的未知样本；其中包含不同光照下橘猫和长条面包。
- 玩家看到训练表现仍高，但未知数据错误明显增多。
- 玩家必须调查两个不同误判样本，再回答“它们共同暴露了什么”，形成最小证据链，而不是点一下就过关。
- 如果玩家在第一次训练后选择“89% 已经证明修好了”，游戏不会立刻弹红叉，而会真的记录一次临时放行，并用后续现场误判把错误理论变成案件证据。
- 小析随后命名此前看到的是“训练集”、新样本是“测试集”；玩家先通过证据意识到当前观察信息存在盲区。
- 只有完成证据推理后才进入修复。

### 阶段 3：过拟合陷阱与修复（约 8～12 分钟）
- 解锁决策树与 KNN。
- KNN 的 `k=1` 作为“几乎记住训练数据”的复杂方案：训练表现可接近 100%，但噪声与异常点导致隐藏测试表现下降、边界破碎。
- 第一次修复先要求玩家故意做一次 `k=1` 极端实验；看到训练 100% / 未知样本下降后，玩家必须自己选出最合理解释，之后才正式揭示“过拟合”。
- 修复阶段使用有限正式审计预算；训练免费，但未知审计消耗额度。改特征 / 模型后必须重新留下实验前预测，鼓励“我要验证什么”而不是穷举。
- 每次未知审计会写入 `CASE_NOTES.LOG`，同时记录预测是否命中。过拟合出现后，玩家必须先从记录里亲手指出“旧分更高、未知反而更差”的那次实验，之后才能解释原因。
- 过拟合后技术组解锁“表面纹理 / 长宽比例”两个备用观察通道；玩家先读完两个模块，再重新开放特征/模型配置。
- 至少两条合理通关路径：
  1. 使用更稳健特征 + 线性分类器；
  2. 使用更稳健特征 + 简单决策树或较平滑的 KNN（k=5）。
- 通关后才正式揭示“过拟合”一词。

## 核心实验循环
剧情关卡与无尽模式共享同一条认知循环：

`观察证据 → 提出假设 → 锁定预测 → 做实验 → 查看未知结果 → 解释偏差 → 修改假设`

难度来自证据不完整、实验预算和多种合理候选，而不是来自晦涩术语。关键判断都采用“先选草稿 → 明确锁定 → 才反馈”的方式；答错允许继续修正。短手工案件把第一次被证据推翻视为正常的假设修正：仍可保留 S，但连续失误会快速降级，避免把科学试错做成“一次猜中答案”的考试。

### 调查局宏观框架

玩家第一次进入时仍从 `CASE 001` 的事故现场开始，不先展示一个内容稀薄的 meta 菜单。CASE 001 结案后通过一次 `CLEARANCE GRANTED` 完成身份转变，从实习调查员进入正式调查员，并首次开放调查局 Hub：

- **案件板**：只放手工正式剧情案件。当前是 `CASE 001 → CASE 002 → CASE 003 → CASE 004 → CASE 005` 的前置序列；每一案新增少量可操作原语，后续案件必须复用旧方法。`CASE 006+` 继续 SEALED，不拿程序化 Duty 假装下一章。
- **训练中心**：承载 Boot Case 000 和未来可明确解释方法的训练内容。
- **调查档案**：只点亮玩家已经亲手遇到的 ML 概念 / 故障，不提前显示未来答案。
- **值班室**：承载程序化监督学习异常。没有未结案件时同时出现 3 份 symptom-only 报告供玩家接案；已经归档的 seed 不重新作为新工单发送；存在未结案件时先处理 / 明确放弃旧案，不能被新报告静默覆盖。

长期进度不使用 XP、金币、属性强化或重复刷关收益。当前仅记录正式案件最佳报告、训练案件是否完成、已经处理过哪些不同 Duty 病症；至少独立处理三类不同程序化故障后身份显示为“独立调查员”，表达经验广度而不是数值战力。

单案件结案必须回流到调查局：`接案 → 调查 → 结案 → 档案更新 → 返回 Hub → 选择下一份工作`。详细约束见 `GAME_ARCHITECTURE.md`。

### 剧情案件检查点
- Story Case 001 是 20～30 分钟长局，进入调查终端后按 seed 保存版本化浏览器本地检查点；刷新 / 关闭页面不会回标题重置整局。
- 检查点覆盖 reducer 阶段与微节拍，包括已读传感器、误判调查、实验记录、剩余审计预算、已锁定但尚未执行的实验预测和结案状态。
- 审计额度不直接保存为可退款数字，而由既有实验记录与额外审计次数重建；F5 不能返还正式实验预算。
- 再次打开时先进入 `UNFINISHED CASE SAVED / RESOLVED CASE SAVED` 网关，由玩家明确选择继续、查看结案或二次确认清除旧进度。
- 右上角小型 `RESET` 同样需要二次确认，避免误触清空长局；点击其他控件会取消确认态。
- 检查点只保留玩家已经揭示的 public `field-*` 审计信息。内部测试 ID、每样本困难 flags 与 fitted model 参数不进入 Story checkpoint。
- checkpoint 不只验证 JSON 形状，还验证剧情阶段与 micro-beat 的可达顺序、训练 / 审计 / CASE_NOTES 的数值与证据关系、迁移题 correctness 和额外审计额度来源；手改 localStorage 不能伪造结案、实验命中或退款。
- checkpoint reader / writer 使用同一 200KB 上限；超限、隐藏 `test-*` telemetry 等 payload 不会恢复，超限写入也不会覆盖最后一份有效存档。匿名行为日志最多保留最近 500 条并记录被截断数量，使极端长局仍可持续保存。
- 如果浏览器暂时拒绝 localStorage 写入，Story 会显示 `LOCAL SAVE FAILED`，明确告知当前进度尚未保存，并提供“重试本地保存”；恢复成功后警告消失。
- 匿名行为日志跨刷新沿用同一 sessionId，并写入 `SESSION_RESTORED` 事件；结案页允许普通玩家主动导出 JSON，服务于后续真人可用性测试。

## 手工案件序列与监督学习 Duty

CASE 001 不再独自承担整个教学框架。当前内容梯度是：

- **CASE 001 · 失控的分类器**：长篇 onboarding；先学会看训练 / 未知表现、调查错误、经历过拟合。
- **CASE 002 · 被平均数藏起来的人**：指标谜题；总体高分故意与优先病例低召回冲突，玩家通过真实阈值实验满足 `Accuracy ≥80% + 优先病例 Recall ≥75%` 的双约束。
- **CASE 003 · 只在白天正确**：环境谜题；固定简单分类规则，只替换观察通道，在白天历史 / 夜班现场之间寻找稳定线索。允许多种可靠观察通道，不设置唯一魔法按钮。
- **CASE 004 · 验证集见过你**：切分谜题；先从 TRAIN / VALIDATION 身份台账发现同一物品跨 split，再保持模型不变只改切分单位，最后只在零身份重叠验证集上比较候选模型。
- **CASE 005 · 80% 到底是什么意思**：校准谜题；从独立可靠性表发现“排序还对、概率刻度却不可信”，只用 CALIBRATION split 冻结概率映射，再首次解封只读 AUDIT 检查泛化，最后把校准后的真实风险交给既定 65% 风险政策。AUDIT 一旦打开只负责评价，不能再回头调本轮映射。

内容生产原则接近“搭系统”而不是“读章节”：`新增一个原语 → 当场操作它 → 下一案把它和旧原语组合`。因此 CASE 003 会继续要求玩家看分类别召回；CASE 004 又继续复用未知审计、分类别召回、环境捷径与控制变量；CASE 005 再复用 CASE 004 的独立验证与 CASE 002 的阈值决策，把“模型分数”和“真实风险概率”拆开。

`Supervised Investigation / Duty` 保留为可重复的陌生案件迁移层：

### 进入桥接
- 正常产品流程不再把无尽调查与 CASE 001 并列在标题页。新人先完成正式入职；之后从调查局值班室选择一份程序化异常报告。
- 第一次接入值班系统时先显示一张极短模式说明，只讲规则循环，不讲任何案件答案。
- 推荐先完成 **Boot Case 000**：用真实 generator / model / audit 结果做两次控制变量实验，亲手读取实验日志，再完成训练版诊断提交。
- Boot Case 还集中教学三类常见证据阅读：训练满分但现场下降、总体分掩盖少数类、历史 / 现场环境变化。这些解释**只存在于训练案件**。
- Boot 结束后保存版本化本地完成标记；正式无尽仍可直接进入，训练案件也可主动重玩。

### 正式无尽原则
- sticky `NEXT OBJECTIVE` 只回答“下一步缺什么动作 / 证据”，绝不回答“哪个字段 / 模型 / 病因是对的”。
- 正式模式不会动态把某个指标解释成“过拟合 / 漂移 / 类别不平衡”；审计只显示客观分数、分类别召回与门槛 PASS/FAIL。
- `调查手册` 是玩家主动打开的静态方法论备忘录，不是按当前案件生成的提示器。
- 手册与正式审计只提供 `TRAIN / FIELD / 召回` 的字面读法；“召回 = 某一类真实样本中有多少被正确找出”属于仪表说明，不属于当前案件解释。
- 病因必须在世界中有原始证据，但 cause-specific 原始事实不能开局自动摊牌。精确类别构成、历史 / 现场批次、采集质量记录统一作为玩家主动复核的 `H-COVERAGE / H-CONTEXT / H-RECORDS`；查到“没有异常”也必须能够作为排除竞争原因的证据。

- 每个 seed 程序化生成一个单人分类案件。
- 当前四类真实故障：**特征不足、训练噪声 / 过拟合、分布漂移、类别不平衡**。
- 每类故障有多组案件语境；四个传感器通道会随 seed 重排，不能背“永远点后两个”。
- 玩家能看到训练标签与无标签现场特征分布，但 Formal Duty 不再把四个传感器统一显示成“旧样本差异 X/5 / 现场变化 Y/5”的答案排行；要判断字段价值，必须切换 `FIELD MATRIX` 的投影亲自观察结构。
- 每宗程序化 Duty 先复现 generator 选出的真实故障部署 baseline。baseline 前三条 causal story 全部 `SEALED`；之后玩家先选择复核 `H-COVERAGE / H-CONTEXT / H-RECORDS` 中的一条，再用 `H-FIELDS / H-MODEL` 的 fields-only / model-only 实验验证“什么干预真正会改变世界”。现在三类来源的 positive finding 都不再和单一病因一一对应：其他病因也可能带着真实但非主因的上游类别覆盖偏斜、运营批次变化或历史质量复核告警。玩家必须把原始事实和受控实验后果组合起来判断，而不是看哪个资料夹亮了。生成器同时保证三份来源中至少保留一份 `CLEAR`：允许一到两条真实 benign confound，但不能把三条来源都做成 SIGNAL 后又碰巧没有可执行的 competing-axis null，导致 falsification gate 永远无法满足。
- 原因资料不能在第一次 baseline 后一次性全点开。**第一次 baseline 获得 1 次 causal-source 解封额度；之后只有此前没有审计过、且相对上一轮只改字段或只改模型的正式配置才再获得 1 次。重复配置与字段 + 模型同时改动都不会解封，未使用额度可以保留**，已经打开的资料也可随时回看。这样 Duty 把来源复核变成由真正的实验进度赚取的调查资源，而不是靠重复 baseline 刷开三份档案。
- 训练不耗预算；正式未知审计初始只有 5 次。每次审计前必须预测未知表现。
- 正式审计返回的现场误判不是静态结果卡：玩家可以点击错误记录，把对应 `field-*` 样本重新定位到 `FIELD_MATRIX`，并把亲手检查过的错误写入 `CASE_LEADS.LOG`。第一次 baseline 失败后，`NEXT OBJECTIVE` 会先引导玩家打开至少一条具体误判，再进入 causal-source 取证；这是节奏引导而非硬结案 gate，避免玩家因为错过旧错误卡而被软锁。
- 结案要求先找到可靠方案，再提交病因。仅有两个不同配置不够：至少要有一组 fields-only / model-only 对照让 FIELD 或最低召回发生 ≥12pt 的 material change，并从 `EXPERIMENTS.LOG` 引用这组区分性证据；而且这组受控对照必须至少有一个端点就是可靠配置。不能在历史别处用 mixed change 找到一个可靠方案，再拿另一组与修复无关的 material 对照替它解释“为什么修好了”。repeat 与同时改字段+模型都不能完成归因。诊断答错后必须取得新的 material controlled evidence，并在下一份证据包里包含它。
- **支持证据不等于调查完成。** 在可靠方案 + material 实验之外，玩家还必须真正排除一个竞争解释：要么主动复核的 causal source 返回 `clear`，要么在 fields-only / model-only 审计前先留下“应该明显改善 / 应该明显恶化 / 应该基本不变”的方向性因果预注册，而结果最终几乎不起作用、使对应假设变成 `WEAKENED`。方向猜错不会抹掉实验事实，但玩家不能再用笼统的“反正会变”回避对干预后果的判断。如果 FIELD 与最低召回都达到 material 变化却方向相反，实验会显式记为 `TRADEOFF / 指标冲突`：它仍证明该干预轴会改变世界，但不会被算成“改善”或“恶化”的方向预测命中，也不能伪装成 null 反证。干预型反证必须针对当前支持证据的**另一条轴**，并从该支持实验至少一个端点的**完整配置**出发：例如 fields-only 的 material support 后，model-only null 必须以 support 的旧端点或新端点为一侧，再只换模型；不能仅仅沿用同一套字段，却拿两种与 support 端点都不同的模型做 null。model-only support 的 fields null 同理。既不能拿另一个 fields-only null 自我抵消，也不能用局部上不连通的第三套配置代替真正的竞争解释检验。没有预注册的弱变化仍会进入实验日志，但不能事后包装成正式反证。竞争假设状态会累积同一轴的全部受控实验：只有 material 为 `SUPPORTED`，只有弱变化为 `WEAKENED`，两者都出现则显示 `CONTESTED`，避免“最后一次实验”抹掉此前相反证据。已经成立的“material support + 独立竞争轴 null”因果证据包也不会因为玩家之后继续做另一项 material 探索而自动失效；只有错误诊断后的 fresh-evidence 边界会主动淘汰旧证据；重试时 material support 与用于补全它的 competing-axis null 都必须来自上一次诊断之后，不能把旧反证重新包装成新因果包。这样系统奖励继续实验，而不是惩罚玩家在已经会结案时继续追问。结案时引用的两条支持记录还必须是玩家当时真实连续执行的一次实验；不能从更早和更晚的两次审计中跨过中间实验，事后拼出一个从未真正执行过的“单变量对照”。这保证预注册、干预和结果属于同一条可复盘的因果链。最终病因还必须和引用证据的因果轴一致：不能拿明确支持 `H-FIELDS` 的修复实验却把报告写成“模型过拟合”，也不能拿 `H-MODEL` 支持去解释字段/环境类病因。对于能由来源直接识别的三类病因，还必须亲自复核对应的正向来源：`overfit-noise → H-RECORDS`、`distribution-shift → H-CONTEXT`、`class-imbalance → H-COVERAGE`，且该来源必须实际返回 `signal`；不能只用另一份 `clear` 来源完成反证后，靠猜病因名称直接结案。`feature-gap` 没有专属来源，仍由字段轴 material support + 独立反证建立。系统允许玩家选择证据不完整的诊断以暴露思路，但会锁住提交并指出缺失环节。来源反馈还要区分“尚未复核”和“已经复核且为 CLEAR”：前者引导玩家回到因果线索补事实，后者明确告诉玩家当前病因已被直接反驳，并把下一步指回诊断，而不是继续假装多查一次来源就能补强同一个故事。syndrome 名称只有在“有支持，也有独立反证”之后才出现。
- **原因来源预判是可选复盘，不是取证门槛。** 每次有限的 causal-source review 仍然有真实机会成本，但 READY 来源可以直接复核。玩家如果愿意，可以在打开前预判该来源会给出 `SIGNAL` 还是 `CLEAR`；预测在来源打开前可修改，打开后锁定并显示 HIT/MISS。由于 benign source confound 的部分结果由未公开 seed bucket 决定，这种预判不计分、也不阻塞取证；真正强制的“先写下预期，再看结果”只保留在可由受控实验验证的因果干预上。旧 v6 存档若已有来源复核但没有历史预判，继续兼容且不伪造命中记录。
- 可靠方案不只看 Accuracy：**总体未知准确率 ≥85%，且两个类别召回都 ≥75%**，因此类别不平衡案件会故意出现“总体 93% 但少数类召回 50%”的假好成绩。
- `EXPERIMENTS.LOG` 会标记 `BASELINE / 只换字段 / 只换模型 / 两者都换 / 复现实验`；引用两条记录后会生成只含客观变量 / 指标变化的 `EVIDENCE_COMPARE`。下一次训练前也会预览当前配置相对上一条记录属于哪种变化，避免花完额度才发现自己同时改了两个因素。
- 案件结束按实验次数、现场预测、方向性因果预注册、额外额度、单变量对照与混合改动给调查评级；**因果方向猜错不会让证据失效，但每次 miss 会扣 3 分**。单变量实验设计奖励最多只计算前 2 次：两次已经足够建立“支持 + 竞争轴反证”的核心证据结构，之后继续实验仍然允许且可能有调查价值，但不会因为重复做 controlled run 而把评级越刷越高。原因来源预判改为**可选复盘**，并在结案中保留玩家主动留下的 HIT/MISS，但**不计调查评级，也不阻塞取证**：生成器为了维持病因歧义，会让部分 benign coverage / batch / quality signal 跨 syndrome 出现，其中一些取决于未公开的 seed confound；在来源打开前并不存在足够公开事实让玩家稳定预测其 SIGNAL/CLEAR，因此不能把这部分随机性变成强制点击或评分。真正强制“先承诺、后揭晓”的因果预注册只保留在可由受控实验验证的 fields-only / model-only 干预上。旧存档没有历史来源预判时继续兼容。结案报告会显示两类预测记录，并同时封存最终配置、引用的实验记录、亲手检查的现场 / 档案证据、**真正支持最终病因的正向事实**，以及**实际让报告通过 gate 的那条独立反证**。现场误判不会只留下“检查过 N 条”的计数，而会按 `E## FIELD-###：实际类别 → 模型判断` 封存最近的具体失败样本，让开局亲手查看的事故证据在最终案卷里仍可追溯。对于有专属正向来源的病因，`CAUSAL SUPPORT` 保存对应来源的 `SIGNAL` 与完整 finding，而不是只留下“查过这份来源”的标签；`feature-gap` 没有专属来源，则明确记录其正向支持来自被引用的 material 单变量干预。如果反证来自原因来源，报告写明哪份来源返回 CLEAR；如果来自干预实验，报告写明是哪两条 E 记录组成了竞争轴 null 对照，避免支持或反证只存在于系统内部布尔 gate、玩家结案后却无法复盘。
- 正式无尽进度按 seed 保存在版本化浏览器本地 session：刷新不会返还正式审计额度，错误诊断锁与证据引用状态也会恢复；模式入口会显式显示未结案件，放弃旧进度并生成新案需要二次确认。

自动玩法平衡把无尽案件同时交给 evidence-policy 与 random-clicker，而且双方从同一个真实故障 baseline 起步。除“证据策略高成功、5 次随机穷举低成功”的旧门槛外，现在还自动检查 baseline 不能已经可靠、案件必须存在 material 单变量干预、evidence-policy 必须真正取得区分性证据；生成器退化成“开局已修好 / 没有能区分解释的实验 / 乱点也能过”时单测直接失败。

## 状态机
`briefing → inspect_data → choose_features → choose_model → train → first_success → hidden_test → inspect_errors → iterate → overfit_reveal → final_audit → transfer_question → complete`

关键守卫：
- 未选择至少 2 个特征不能训练。
- 未训练不能进入测试。
- 阶段 1 必须在散点图上找出一个真实异常旧样本，并读懂一次模型决策边界探针。
- 阶段 2 首次测试后，必须查看至少 2 个不同错误样本并完成证据推理才能进入下一步。
- 修复阶段正式未知审计有有限额度；额度耗尽可申请额外审计，但影响评级，不造成死局。
- 过拟合揭示前必须从 `CASE_NOTES.LOG` 选中真正反常的一次实验。
- 最终成功要求隐藏测试准确率 ≥ 0.84，且关键橘猫子集错误 ≤ 1。
- “训练集 100%”本身永远不是成功条件。

## 核心机制
- 数据：猫/面包两类二维点；底层样本含 4 个语义特征，玩家每次选择两个投影到二维散点图。
- 特征候选：颜色暖度、轮廓圆度、纹理粗糙度、长宽比。
- 模型：线性分类器、浅层决策树、KNN（k=1/5）。
- 每次训练后即时刷新决策边界、训练表现和当前可用测试表现。
- 错误样本可点击，显示“真实类别 / 模型判断 / 当前两项特征”，并在散点图中高亮。
- 隐藏测试标签仅在测试阶段通过评估模块返回聚合结果与错误列表；普通 UI 不持有完整测试标签表。

## AI 助理“小析”
- 默认每个阶段仅给一句当前任务。
- 连续失败 1 次：一级提示，只提醒看某种现象。
- 连续失败 2 次：二级提示，指出可能应换特征或降低复杂度。
- 连续失败 3 次或主动请求三级提示：解释失败原因，但不替玩家选择。
- 在玩家亲眼看到测试失败前，不出现“测试集 / 泛化 / 过拟合”的答案型解释。

## 风险与削减策略
- **风险：教学内容过多。** 只保留一次“成功→意外失败→过拟合”认知反转；公式完全不出现。
- **风险：二维特征切换让玩家困惑。** 每次只允许选择恰好两个特征，并在坐标轴写中文语义名。
- **风险：为了剧情牺牲真实 ML。** 所有分数均由浏览器本地模型实时计算；剧情只负责解释为何要做下一步。
- **风险：隐藏测试泄露。** 游戏 runtime 不再提供“显示完整隐藏测试真值”的 Debug API；正式流程只通过受控审计动作返回聚合指标与当前误判证据。
- **风险：手机 UI 过密。** 不追求复杂移动端，仅保证主要选择、训练、审计、通关可完成。

## 验收标准
- 首屏 30 秒内有单一明确行动按钮。
- 标准路线 5 分钟内完成第一次训练成功。
- 至少一次出现训练高、隐藏测试明显较差的真实结果。
- k=1 在预设固定种子下产生可解释的过拟合边界与测试下降。
- 至少两种模型/特征组合可达到最终成功条件。
- 玩家能点开误判样本并根据修改看到错误变化。
- 所有关键教学文字单段 ≤ 80 汉字。
- 标准路线与 5 种典型错误路线均不会进入无法继续状态。
- 测试作弊码可快速进入 CASE 001 的 ERRORS / OVERFIT / REPAIR / FINAL / CLOSED 等合法正式检查点，并可打开指定 seed 的 Duty；历史 `?debug=1` 不再拥有特殊权限。
- 类型检查、单测、构建与 CI 全通过。
