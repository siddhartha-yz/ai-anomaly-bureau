# 《AI异常调查局：失控的分类器》产品设计

## 一句话定位
一款让零基础大学新生通过“调查橘猫被识别成面包”的事故，在约 20～30 分钟的首次认真游玩中亲手经历数据、特征、模型、测试集与过拟合的浏览器机器学习入门游戏。

## 玩家画像
- 大一新生；可能完全没学过机器学习、线性代数、概率论和 Python。
- 对 AI 有兴趣，但对公式、代码和英文术语有明显心理门槛。
- 第一次社团活动中需要迅速获得“我能做到”的反馈。

## 学习目标
通关后，玩家能够用自己的话解释：
1. 模型只能利用提供给它的数据与特征。
2. 训练集上表现好，不代表未知数据上也表现好。
3. 模型越复杂不一定越好；过度迎合训练数据会伤害未知数据表现。
4. 测试集用于检查模型面对未知数据时的表现。
5. 错误样本比单个准确率数字更能帮助定位问题。

## 第一关体验流程
### Cold Open：事故发生（约 2～3 分钟）
- 先进入校园夜间监控录像，而不是直接掉进 ML 工作台。
- 玩家亲眼看到橘猫被系统输出为 `BREAD / 87%`，并完成第一个唯一显眼操作：“这明明是一只猫”。
- 系统显示 `CAT ≠ BREAD / CONFLICT DETECTED`，小析才介入说明案件目标：找出机器人学错了什么，并让它面对没见过的新样本也能判断稳定。
- 这段同时教会玩家游戏的点击视觉语言，不要求任何 ML 背景。

### 阶段 1：第一次成功（约 5～7 分钟）
- 身份：现场调查员 → 传感器调查员 → 模型工程师。
- 工作台采用 progressive disclosure：还没用到的模型、特征工具直接隐藏，而不是全部同时变灰摆在屏幕上。
- 玩家先肉眼判断旧样本是否形成两团，再分别读取“颜色暖度 / 轮廓圆度”两个当前观察通道，理解机器人并没有像人一样直接看懂图片。
- 玩家亲手装载唯一开放的直线分类器并训练；训练表现高后，必须先留下“它是否真的修好”的预测，之后才开放未知样本验证。
- 此时仍不提前解释训练集、测试集、泛化、过拟合等术语。

### 阶段 2：意外失败（约 6～8 分钟）
- 身份切换为系统审计员。
- 首次揭示一批此前不可见的未知样本；其中包含不同光照下橘猫和长条面包。
- 玩家看到训练表现仍高，但未知数据错误明显增多。
- 玩家必须调查两个不同误判样本，再回答“它们共同暴露了什么”，形成最小证据链，而不是点一下就过关。
- 小析随后命名此前看到的是“训练集”、新样本是“测试集”；玩家先通过证据意识到当前观察信息存在盲区。
- 只有完成证据推理后才进入修复。

### 阶段 3：过拟合陷阱与修复（约 8～12 分钟）
- 解锁决策树与 KNN。
- KNN 的 `k=1` 作为“几乎记住训练数据”的复杂方案：训练表现可接近 100%，但噪声与异常点导致隐藏测试表现下降、边界破碎。
- 第一次修复先要求玩家故意做一次 `k=1` 极端实验；看到训练 100% / 未知样本下降后，玩家必须自己选出最合理解释，之后才正式揭示“过拟合”。
- 每次未知审计会写入 `CASE_NOTES.LOG`，让玩家比较旧样本表现、新样本表现、特征与模型，而不是凭记忆乱试。
- 过拟合后技术组解锁“表面纹理 / 长宽比例”两个备用观察通道；玩家先读完两个模块，再重新开放特征/模型配置。
- 至少两条合理通关路径：
  1. 使用更稳健特征 + 线性分类器；
  2. 使用更稳健特征 + 简单决策树或较平滑的 KNN（k=5）。
- 通关后才正式揭示“过拟合”一词。

## 状态机
`briefing → inspect_data → choose_features → choose_model → train → first_success → hidden_test → inspect_errors → iterate → overfit_reveal → final_audit → transfer_question → complete`

关键守卫：
- 未选择至少 2 个特征不能训练。
- 未训练不能进入测试。
- 阶段 2 首次测试后，必须查看至少 2 个不同错误样本才能进入下一步。
- 最终成功要求隐藏测试准确率 ≥ 0.84，且关键橘猫子集错误 ≤ 1。
- “训练集 100%”本身永远不是成功条件。

## 核心机制
- 数据：猫/面包两类二维点；底层样本含 4 个语义特征，玩家每次选择两个投影到二维散点图。
- 特征候选：颜色暖度、轮廓圆度、纹理粗糙度、长宽比。
- 模型：线性分类器、浅层决策树、KNN（k=1/5）。
- 每次训练后即时刷新决策边界、训练表现和当前可用测试表现。
- 错误样本可点击，显示“真实类别 / 模型判断 / 当前两项特征”，并在散点图中高亮。
- 隐藏测试标签仅在测试阶段通过评估模块返回聚合结果与错误列表；普通 UI 不持有完整测试标签表。

## AI 助理“小析”
- 默认每个阶段仅给一句当前任务。
- 连续失败 1 次：一级提示，只提醒看某种现象。
- 连续失败 2 次：二级提示，指出可能应换特征或降低复杂度。
- 连续失败 3 次或主动请求三级提示：解释失败原因，但不替玩家选择。
- 在玩家亲眼看到测试失败前，不出现“测试集 / 泛化 / 过拟合”的答案型解释。

## 第一版范围
必须完成：一个完整单人关卡、三类真实模型、四项语义特征、固定种子数据、SVG 决策边界、训练/测试对比、错误样本、分级提示、迁移问题、debug 面板、六类自动路线、行为日志导出、自动测试、CI。

明确不做：联网、多账号、多人协作、排行榜、养成、商店、语音、大模型 API、神经网络训练、大地图、多关卡内容。

## 风险与削减策略
- **风险：教学内容过多。** 只保留一次“成功→意外失败→过拟合”认知反转；公式完全不出现。
- **风险：二维特征切换让玩家困惑。** 每次只允许选择恰好两个特征，并在坐标轴写中文语义名。
- **风险：为了剧情牺牲真实 ML。** 所有分数均由浏览器本地模型实时计算；剧情只负责解释为何要做下一步。
- **风险：隐藏测试泄露。** 普通流程只通过受控审计动作读取测试评估结果；debug=1 才可显示真实标签。
- **风险：手机 UI 过密。** 不追求复杂移动端，仅保证主要选择、训练、审计、通关可完成。

## 验收标准
- 首屏 30 秒内有单一明确行动按钮。
- 标准路线 5 分钟内完成第一次训练成功。
- 至少一次出现训练高、隐藏测试明显较差的真实结果。
- k=1 在预设固定种子下产生可解释的过拟合边界与测试下降。
- 至少两种模型/特征组合可达到最终成功条件。
- 玩家能点开误判样本并根据修改看到错误变化。
- 所有关键教学文字单段 ≤ 80 汉字。
- 标准路线与 5 种典型错误路线均不会进入无法继续状态。
- debug=1 可跳关、切种子、查看参数、自动路线与导出 JSON。
- 类型检查、单测、构建与 CI 全通过。
