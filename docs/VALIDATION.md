## Chromium 真实渲染与点击验收

服务器仍没有 sudo，也没有系统级 Chromium 运行库；但已将所需 Chrome 共享库、CJK QA 字体、浏览器 profile 全部放在被 Git 忽略的 `.tooling/` 中，并通过本地 Chrome DevTools Protocol 完成真实 headless Chromium 验收，不修改系统环境。

1920×1080 正常玩家路线已由真实 DOM 点击完整跑通：
1. 标题页进入案件。
2. 观察样本、选择特征、选择线性模型、第一次训练。
3. 进入未知样本审计并打开真实误判证据。
4. 进入修复阶段，故意选择 KNN k=1 触发训练 100% / 未知表现下降的过拟合。
5. 返回修复时确认“大阶段过场”不会重复播放。
6. 改用稳健特征 + 线性模型，未知审计恢复到 100%。
7. 完成迁移问题并进入 `CASE CLOSED`。

真实截图回归还发现并修复了：
- 悬浮小析覆盖模型工具盒；
- 修复阶段双按钮在窄栏中逐字换行；
- 错误检查箭头指向了错误的证据区域；
- 点击误判后玩家实际看不到下方证据卡；
- 证据列表暴露默认浏览器横向滚动条；
- `.app-shell { overflow: hidden }` 导致 sticky 任务卡失效；
- 奖励提示遮挡 sticky 任务卡；
- 过拟合后重新进入修复会重复播放 PHASE 03；
- 小析把上一阶段请求过的提示错误带入后续剧情。

`.tooling/` 中的 Chrome、运行库、字体和 QA 截图均不提交到 Git。Windows 真机截图仍作为最终美术判断基准；服务器 headless Chromium 主要用于布局、遮挡、流程和状态回归。

## 第一轮真实玩家测试最值得观察的内容

招募 5～8 名没有 ML 基础的大一新生，优先记录：
- 首屏到第一次有效点击是否 < 30 秒。
- 是否能在 5 分钟内完成第一次训练。
- 第一次看到 88.9% 训练表现时，是否误以为已经彻底解决问题。
- 测试跌到 66.7% 后，是否主动查看误判，而不是继续盯总分。
- k=1 出现训练 100% / 测试 79.2% 时，能否用自己的话说出“它太记旧数据了”。
- 是否理解换特征会改变模型实际看到的数据，而不只是换图表外观。
- 迁移问题能否不靠记忆“过拟合”术语答对。
- 完成后是否愿意继续参加下一次社团活动。

真实测试后，应优先修改造成误解或卡住的步骤，不优先增加新关卡、养成、多人或视觉装饰。
