| 纹理 + 长宽比 | KNN k=1 | 100%（0 错） | 79.2%（5 错） |
| 纹理 + 长宽比 | KNN k=5 | 88.9%（4 错） | 100%（0 错） |

这些指标由模型实时计算，不是 UI 写死结果。教学反差满足：
- 阶段一：初始方案在旧样本上足够成功，建立信心。
- 阶段二：相同方案遇到未知样本明显下降。
- 阶段三：k=1 取得训练 100% 但测试下降，再引出“过拟合”。
- 最终：至少直线、浅树、k=5 三种路线可在稳健特征上通过审计。

## 浏览器视觉验收限制

已尝试使用宿主提供的 Playwright 浏览器会话进行 1440×1000 实际界面检查，但该服务器缺少 Chromium 二进制；进一步使用项目内 Chrome 时，宿主又缺少 `libatk-1.0.so.0` 等系统图形库，且当前环境没有免密 sudo。

因此本轮没有伪称完成真实 Chromium 截图/点击验收。已用以下验证替代：
- strict TypeScript；
- 20 个核心/状态/路线测试；
- production build；
- 实际 HTTP 启动检查；
- CSS 桌面/980px/600px 响应式规则检查。

进入真实新生测试前，仍建议在有完整浏览器环境的机器上人工走一次桌面与手机流程。

## 第一轮真实玩家测试最值得观察的内容

招募 5～8 名没有 ML 基础的大一新生，优先记录：
- 首屏到第一次有效点击是否 < 30 秒。
- 是否能在 5 分钟内完成第一次训练。
- 第一次看到 88.9% 训练表现时，是否误以为已经彻底解决问题。
- 测试跌到 66.7% 后，是否主动查看误判，而不是继续盯总分。
- k=1 出现训练 100% / 测试 79.2% 时，能否用自己的话说出“它太记旧数据了”。
- 是否理解换特征会改变模型实际看到的数据，而不只是换图表外观。
- 迁移问题能否不靠记忆“过拟合”术语答对。
- 完成后是否愿意继续参加下一次社团活动。

真实测试后，应优先修改造成误解或卡住的步骤，不优先增加新关卡、养成、多人或视觉装饰。
